# 登入隔離版 0.3.5

> **已停止測試並隔離。** 實機確認兩座原版 Blueprint 無法直接搭配新的建築 ID：26 級設計建築持續顯示轉圈中的無效欄位，同次測試也出現世界帕魯行為異常。此版只證明連續兩次登入不再崩潰，不得重新安裝或繼續功能測試。

> **存檔救援：** 不可直接刪除兩個 `PRF_*` 建築列，否則含有舊建築的測試世界會卡在讀取中。遊戲端目前改載入 `recovery/facilities.recovery.json`：保留相同 ID，但把兩座故障機器替換成無工作、無互動、無科技解鎖的木桌佔位物，僅供進入測試世界後拆除。

## 這一版能測什麼

- 兩項科技是否出現在 1 級普通科技的空位，不再與古代科技重疊。
- 26 級設計建築改用原版大型孵化器 Blueprint 後，是否能開啟介面並放入蛋；建築 ID 仍是 `PRF_EggResourceProcessor`。
- 36 級設計建築改用原版古代孵化場 Blueprint 後，是否能開啟介面並指派兩隻親代。
- 完全不載入自製 Blueprint PAK，也不啟用 native 掛鉤時，能否穩定登入全新世界。
- 兩座建築在本輪功能測試中都不要求供電，建造材料都是木材 ×1。

這一版只供全新拋棄式測試世界。它刻意不執行自動孵化、支解、掉落或基地倉儲提交，只用來排除登入崩潰並驗證原版介面。不能用主要存檔。

## 測試順序

1. 使用全新的單人測試世界，先確認原版世界可以正常載入。不要沿用 0.3.1 已累積九筆孵化紀錄的建築；安裝後必須拆除並重建兩座測試建築。
2. 開啟科技頁，在 1 級普通科技列確認「蛋資源處理機」與「資源繁殖場」各自占用空位；說明文字分別標示 26／36 級設計進度。
3. 先建造蛋資源處理機，確認建築可互動、介面可開啟並可放入一顆蛋；本輪不要等待自動支解。
4. 再建造資源繁殖場，確認介面可開啟，指派面板可放入兩隻親代；本輪不要驗收自動支解。
5. 回到標題畫面再重新進入同一測試世界一次，確認沒有新增 CrashContext。
6. 結束遊戲後執行 `tools\collect_test_evidence.ps1`，把結果交回本任務。

## 通過條件

- UE4SS 記錄不得啟動 `PalResourceFactoryNative`，遊戲目錄不得載入 `PalResourceFactory_P.pak`。
- 兩個科技都位於 1 級普通科技空位，沒有遮住右側古代科技。
- 26 級設計建築可開啟並放入蛋；36 級設計建築可開啟並指派兩名親代。
- 連續兩次進入全新測試世界都不產生新的 CrashContext。
