# 單蛋落地出料實驗 0.2.0

0.1.0 的單蛋入庫已由日誌與使用者重進測試確認：一顆蛋消耗、兩種材料各 3 個入箱，沒有新增活帕魯。0.2.0 保留後代／支解計算，改成原版支解機的地面掉落出口；**地面出料、拾取與帕魯搬運尚待本版遊戲內驗證**。安裝狀態以 `build-settlement-test/install-receipt.json` 與遊戲目錄讀回為準。不是已完成的自動建築 MOD。

這是 `PalResourceFactorySettlementTest` 的更新，按鍵仍為 **Ctrl + Alt + F9**；Ctrl + Alt + F8 獨立預覽不變。F9 會消耗蛋，只能在拋棄式本機單人測試世界執行。

## 實作範圍

1. 只處理本機單人世界、原版單顆孵化器內已完成孵化的一顆蛋。不是自製建築互動或自動排程。
2. 複製完整原版後代資料，沿用已實機驗證的原版支解機率函式，不建立場景帕魯，不加入帕魯終端。
3. 先把當次材料結果保存到本模組的 `settlements/<動態蛋識別碼>.txt`。後續重試沿用相同清單，不重抽。
4. 沿用原版扣蛋計畫，讀回確認蛋格已空；原版容器通知負責清除孵化完成狀態，原版動態物品清理入口負責清除蛋資料。
5. 從孵化器座標沿自身前向約 2 公尺、抬高 0.6 公尺送出原版掉落要求。原版支解機使用的入口負責物品容器、地面物件、拾取及後續搬運可用性；不建立假物品外觀，不直接呼叫或更改帕魯 AI。
6. 不尋找或直接寫入任何箱子，不要求箱子有容量。箱子只用於後續原版搬運；要允許材料，不能只勾選「帕魯蛋」。

沒有按鍵時，只檢查一個原子旗標；不保留跨幀世界物件、不掃描物件、不自動孵化、不接管野生 AI、不背景重試。

## 安裝後才適用的遊戲測試

本文件不代表已安裝。先確認遊戲關閉，再安裝獨立測試 DLL；不啟用舊 `PalResourceFactoryNative` 或故障建築包。

1. 進入拋棄式單人世界。在平坦、開闊的基地放一座原版單顆孵化器，四周至少留 3 公尺空間。第一輪先不放基地工作帕魯，箱子可以不存在。
2. 放一顆可消耗的蛋，等孵化完成，**不要領取**。世界內只能有一座已完成的原版單顆孵化器。
3. 玩家站離孵化器與預期出口約 5 公尺，按一次 **Ctrl + Alt + F9**，等待約 10 秒。預期孵化器變空、前方地面出現原版材料、終端不增加活帕魯。不要立即退出或反覆按鍵。
4. 先截圖記錄掉落，再靠近確認玩家能拾取，記下物品名稱及數量。材料種類以該顆蛋的原版結果為準，日誌 `GROUND_REQUEST item=... count=...` 會列出預計材料；不是每種蛋都固定掉同樣材料。
5. 第二顆蛋測搬運：先放一隻具有搬運適性的基地帕魯，以及一個允許所有物品且有空位的箱子。重複單蛋操作後站遠，確認是帕魯搬起地面材料、走到箱子存放，而不是材料直接入箱。
6. 材料已拾取／入箱後正常退出重進，核對蛋仍空、材料不增加或消失。這是收納後重載，不代表未拾取地面物品永久保存。

若凍結、崩潰或日誌出現 `REFUSED`，保留 `UE4SS.log` 與本模組 `settlements` 目錄，不刪收據、不連續重試。若蛋消失但沒看到材料，先查玩家背包或是否已被搬走；本測試仍可能扣蛋後生成失敗，不提供返還路徑。

## 日誌界線

- `READY version=0.2.0-manual-ground-test`：新版已載入，輸出為 `vanilla-ground`；不是結算成功。
- `RNG_CLAIMED`：已在磁碟認領這顆蛋的機率呼叫。
- `FIXED_RESULT_SAVED`／`FIXED_RESULT_REUSED`：已保留／沿用原版清單。
- `APPLY_BEGIN ... no-chest-writes=true`：開始不可逆扣蛋；中斷後禁止自動重播。
- `EGG_READBACK_OK`：原版蛋格已空、完成資料清除，並列出出口世界座標。
- `GROUND_REQUEST item=... count=...`：呼叫原版掉落入口前，列出該種類及數量。
- `GROUND_REQUESTED ... ground-visible=UNVERIFIED hauling=UNVERIFIED`：要求已送出，**不是物品已出現，更不是搬運成功**。收據禁止重播。
- `REFUSED`：前置條件、版本或讀回不符；若已出現 `APPLY_BEGIN`，不要當成「一定沒有扣蛋」。
