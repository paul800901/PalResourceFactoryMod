# 第二台領取／重載修正測試 0.1.4

0.1.3 已觀察到連續出料，但實測活體領取攔截失敗、正常重進後停機。0.1.4 修正原生領取入口，並區分重載後的既有結算紀錄；尚未實機驗證。

- 回到同一單人測試世界即可，不重建、不另加蛋糕。
- 靠近第二台，觀察原有完成蛋是否逐步減少、機器旁是否生成材料。有既存蛋糕時原版仍可能補蛋，故不能只以蛋總數判定是否出料。
- 等待約 30 秒，確認恢復連續出料。已有 GROUND_REQUESTED 的舊蛋只消除恢復的來源，不再給材料；RESOLVING/APPLYING/VERIFIED 等不確定紀錄只隔離該蛋，不重算、不出料，其他蛋可繼續。這不是任意斷線皆無損的保證。
- 有完成蛋時，記下帕魯終端內的後代數，按一次「獲得所有孵化帕魯」，確認沒有取得活體；按鈕仍可能呈現藍色，外观不是判定依據。後台需有 OBTAIN_BLOCKED 或 INPUT_LOCKED，且無取得活體；若成功領到則測試失敗。
- 再正常退出、重進一次，確認仍持續出料；暫不做強制終止或斷網測試。回報後讀回 PRFAncient 的 EXISTING_RECEIPT、RESTORED_SOURCE_REMOVED、EGG_QUARANTINED 及新結算紀錄。
- 若卡住或沒有出料，不拆機、不領取、不反覆重進；先讀日誌定位。
- 第一台未更動；此版限單人整合測試。沒有清除結算紀錄、補發材料或返還蛋／蛋糕。
- 編譯及既有 CTest 通過不等於遊戲內支解成功。
